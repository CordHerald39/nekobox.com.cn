mihomo 的 DNS 问题通常涉及服务器列表、DNS 规则和代理模式三层。先看运行时加载的配置，再用固定目标验证解析路径，避免只修改订阅原文。

## 先读取当前生效配置

从 [mihomo 官方 DNS 配置文档](https://wiki.metacubex.one/config/dns/)核对当前字段。记录内核版本、DNS servers、rules、fallback 或 fake-ip 等选项；图形客户端可能会合并本地覆写，文件原文不一定就是运行时内容。

## 按三层检查

1. **服务器列表**：确认每个服务器类型和地址符合当前文档，删除明显失效或拼写错误的临时项。
2. **规则引用**：确认 DNS 规则引用的名称在服务器列表中存在，默认解析器也有明确值。
3. **接管模式**：确认系统代理、TUN 或 fake-ip 的接管范围，避免用浏览器结果推断所有应用。

先只保留一条测试规则和一个目标域名，修改后重新加载配置。不要把第三方 DNS 地址或未经核验的示例直接当成必然可用方案。

## 用固定目标验证路径

分别记录域名解析结果、连接结果和最终出站。域名失败而 IP 可达时，优先看 DNS；两者都失败时，再回到 [mihomo 规则顺序检查](/articles/mihomo-rule-order/)与节点日志。已有长连接可能保留旧解析，测试前应重新建立连接。

## 逐项回滚

保留修改前的配置和错误时间，确认一个字段恢复后再继续。DNS 配置可能包含内网域名或服务地址，不要把完整配置和订阅凭据上传到公开 Issue。
