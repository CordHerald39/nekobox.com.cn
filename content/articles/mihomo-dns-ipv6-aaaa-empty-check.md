mihomo 的 DNS 服务能返回 IPv4 地址，AAAA 查询却没有地址时，先检查 dns.ipv6。官方文档明确说明，这个字段为 false 时会对 AAAA 返回空解析。这种结果可能来自当前配置，不能单凭一次空响应就判断上游解析服务器失效。

## 这个字段控制哪一层

`ipv6` 位于 `dns` 段中，控制该 DNS 链路是否解析 IPv6。它的作用范围要和操作系统的 IPv6 网络能力分开看：改动 DNS 字段不会替设备分配 IPv6 地址，也不能证明到目标的 IPv6 路由已经可用。

下面是合并到已有配置的局部片段，用于说明空响应的配置条件；不要用它覆盖完整 DNS 配置，也不必为了排错一律关闭此项。

```yaml
dns:
  ipv6: false
```

文档还在解析服务器附加参数中列出 `disable-ipv6`，含义是丢弃 AAAA 回应。排查单台服务器时，也要检查其地址是否带有该参数；不要仅凭 `dns.ipv6` 一个值就排除所有过滤因素。

## 先确认正在查询 mihomo

1. 保存当前配置和核心版本，记录 DNS 实际监听地址、端口以及重载后的 `dns.ipv6` 值。
2. 选一个已确认有 A、AAAA 记录的目标，对同一目标分别查询这两类记录。
3. 让查询明确发往当前 mihomo DNS 监听端点，记录响应状态、地址、时间和相关日志。
4. 再比较应用实际使用的解析路径；浏览器独立加密 DNS 或系统缓存可能使应用绕过这次查询。

不要为了测试而把监听改为所有网卡。已有本机监听通常足以做单机对照。工具没有收到响应与收到了不含地址的响应，也要分别记录，前者还涉及监听、协议或网络路径。

## 何时尝试打开 IPv6 解析

只有确实需要 AAAA 结果时，才在副本中将该字段改为 `true`。保留服务器列表、Fake-IP 模式和路由不变，通过当前核心校验后重载，再对同一目标重复 A/AAAA 查询。

如果 AAAA 恢复但应用连接仍超时，下一步检查设备和实际出站的 IPv6 连通性。代理节点域名解析、目标解析和出站网络也可能分别受不同设置影响；不能用“拿到了 IPv6 地址”代替“IPv6 连接已成功”。

若结果依旧为空，应继续核对目标是否确有 AAAA、规则是否把请求送到预期解析服务器、服务器地址是否带有丢弃参数。Fake-IP 场景还需要区分映射结果与上游真实地址，不能把两个结果直接当成同一种记录比较。

## 保存结果与恢复配置

建议记录修改前后字段值、A/AAAA 响应和新连接结果。无法确认改动收益时，恢复备份中的原值或原本省略的状态，再校验与加载。不要在同一轮同时更换节点、解析服务器和系统 IPv6 设置，否则很难定位差异来源。

解析路径可结合 [mihomo DNS 配置检查](/articles/mihomo-dns-config-check/) 分层查看；映射相关问题参考 [Fake-IP 过滤说明](/articles/mihomo-dns-fake-ip-filter/)。不同版本配置的迁移见 [mihomo 配置版本检查](/articles/mihomo-config-version-migration/)。
