v2rayNG 的订阅更新与 geoip.dat、geosite.dat 更新是两件事。节点列表已经更新，不能说明分流数据库也已经换新。官方 README 提醒，应用的数据下载功能需要可用代理；如果恰好依赖尚未更新的数据才能访问下载源，就可能出现下载环节失败。

## 先确认报错属于哪一步

记录应用版本、更新入口、报错时间和完整错误文字。先判断是下载超时、写入失败，还是更新完成后路由仍与预期不同。订阅 URL 无法获取时，请使用[订阅更新排查](/articles/v2rayng-android-subscription-update-failed/)，不要把两类故障混在一起。

| 现象 | 先检查的证据 |
| --- | --- |
| 更新一直超时 | 当前网络能否访问 README 指向的数据仓库 |
| 下载完成但无法导入 | 文件格式、权限、实际导入路径 |
| 导入后分流不变 | 当前启用的配置、规则类型、目标命中记录 |

## 核对数据源与当前连接

1. 从原始项目 README 中打开 Geoip 与 Geosite 段落，使用其中列出的来源。
2. 保留当前可工作的节点，用同一网络访问数据源，区分整个来源不可达与应用内单次请求失败。
3. 记录下载的是 IP 数据还是域名数据；两者名字相近，但不能互相改名代替。
4. 若应用更新入口失败，按项目文档支持的方式手动导入，不把第三方压缩包直接当作 dat 文件。

官方 README 将应用更新使用的数据指向 Loyalsoldier 相关仓库。这是 v2rayNG 文档列出的来源关系，不代表每个第三方规则集合都能兼容当前客户端。

## 路径存在差异时怎样处理

README 给出的常见位置是 `Android/data/com.v2ray.ang/files/assets`，同时明确说明部分设备路径可能不同。Android 的目录访问权限也会影响文件管理器操作。优先使用客户端提供的导入方式；不要因为文件管理器看不到目录，就清除应用数据或卸载软件。

替换前保留旧文件及其来源记录。导入后按当前版本要求重新加载配置或重启服务，再对同一目标发起一个新连接。对照测试期间保持节点与规则模式不变。

## 如何确认更新有效

挑选一个本来就有规则覆盖的域名或 IP，查看实际命中的规则与出站。域名规则和 IP 规则测试要分开。如果下载与导入均成功，但目标仍走错路径，应转到路由配置排查，而非反复下载相同文件。

需要重新安装时，先看[v2rayNG 官方下载入口核验](/articles/v2rayng-android-download/)。本文核验的是更新方法与资料来源，没有对任何规则库的覆盖率或访问效果作保证。
