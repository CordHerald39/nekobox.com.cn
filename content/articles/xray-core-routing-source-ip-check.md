Xray-core 想按来源设备分流，却发现同一规则没有命中时，先核对核心看到的来源 IP。当前官方文档使用 sourceIP 表示来源地址条件，并注明 source 是别名。它匹配的是进入核心连接的来源，不能把目标网站地址填进去，也不能直接用设备名称代替。

## 来源地址、目标地址和端口分别看

`sourceIP` 是数组，支持 IP、CIDR 等范围格式。`ip` 则用于目标地址条件，两者用途不同。最容易验证的起点是一个明确的单地址或网段；不必为了排错先引入额外数据文件。

端口也要分开：`port` 是目标端口，`sourcePort` 是来源端口，`localPort` 指本地入站端口。访问 HTTPS 的目标端口常见为 443，不代表客户端发起连接时的来源端口也为 443。按来源设备分流时，若额外误加这样的 `sourcePort` 条件，反而会让地址正确的请求无法匹配。

## 从一条范围清楚的规则开始

下面是加入现有 `routing.rules` 的单条 JSON 规则，用回环地址演示来源条件。`direct` 必须是已有的出站标签；该示例只适合来源确实显示为回环地址的本机对照，不能作为所有局域网设备的配置。

```json
{
  "sourceIP": ["127.0.0.1/32"],
  "outboundTag": "direct"
}
```

官方说明，同一规则多个属性必须同时满足。添加域名、网络或入站标签后，要逐一核对这些条件；不能把多个属性理解为“符合任意一个就命中”。规则仍按顺序匹配，前面的宽泛规则可能先处理请求。

## 核对核心实际看到的来源

1. 备份配置，记录核心版本、实际入站标签、目标与当前出站结果。
2. 从准备分流的客户端建立一条新连接，检查访问日志里的来源地址和端口。
3. 确认这个地址是否等于原本预想的设备地址；经过上游代理或地址转换时，核心看到的来源可能已经改变。
4. 在副本里按观察到的来源设置最小范围规则，先保留其他条件不变，完成配置校验后重载。
5. 从命中与不命中的来源分别建立新连接，核对实际出站，再检查未涉及的来源是否保持原路径。

如果核心只看到上游转发程序的地址，就不能靠猜测终端设备 IP 让 `sourceIP` 恢复身份信息。先明确当前网络拓扑与日志证据；也无需为此直接扩大入站监听范围。

## 兼容与回退

本文按当前文档使用 `sourceIP`，文档同时列出 `source` 别名。实际运行核心的版本仍需支持所写字段；若校验失败，恢复原规则并查该版本说明，不要批量改名整个配置中的其他地址字段。

测试完成后记录来源、命中条件、实际出站与请求时间。配置能启动只说明结构通过检查，已有长连接继续走旧路径也不能证明新规则无效。若出现误分流，恢复备份中的规则顺序和条件，重新建立连接验证。

目标端口可结合 [Xray-core port 路由规则](/articles/xray-core-routing-port-range-check/) 检查；请求记录见 [Xray-core 日志配置](/articles/xray-core-log-config/)，完整匹配顺序见 [路由规则指南](/articles/xray-core-routing-rules/)。
