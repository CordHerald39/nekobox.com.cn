“更新失败”和“更新后不能连接”要分开处理。前者通常发生在取回订阅或解析内容的阶段；后者可能已经取得节点，只是新字段、路由或服务端变化影响了连接。先保存原分组，不要删除所有节点后再尝试恢复。

## 看错误发生在哪个阶段

| 观察结果 | 下一步 |
| --- | --- |
| 超时、无法解析订阅域名 | 查网络与请求路径，暂不改节点字段 |
| 返回未授权或禁止访问 | 向服务方核对订阅是否失效、权限是否变化 |
| 请求有内容但导入为空 | 确认返回的是节点格式而非网页 |
| 更新后节点数量改变 | 对照服务方实际节点列表与更新记录 |
| 有节点但连接失败 | 进入连接日志排查，不反复转换订阅 |

这些是排查分支，不是对某个服务方的实测结论。记录错误原文和时间比猜测“机场坏了”更有帮助。

## 用单独测试分组复现

先导出备份，保留当前可用节点。新建日期标记的测试分组，用同一个服务方提供的原始地址更新一次。不要把含访问令牌的链接粘贴到公开转换服务、截图或评论区。

切换 Wi-Fi 与移动网络时每次只改变一个条件，并记录结果。如果开启代理时和关闭代理时的更新表现不同，重点检查请求路径。不要把“能打开服务网站”当作订阅接口一定可用，登录页面与订阅接口可以是两个地址。

## 内容取得了，再判断格式

NekoBox 文档列出的支持格式包括 Clash Meta、V2rayN、Shadowsocks 和相应 sing-box 节点格式；不同类型的 JSON 不能仅凭扩展名混用。[格式判断页](/articles/import-subscription/)解释节点列表与完整配置的差别，[导入教程](/articles/nekobox-formats/)负责实际导入后的字段核对。

如果返回的是 HTML 登录页，先解决地址或访问权限，不把它转换为 YAML。服务方提供多个客户端订阅时选择明确适配的类型。解析问题应附脱敏错误、版本和格式名称，而非完整订阅正文。

## 1.4.2 升级后注意本地覆写

1.4.2 发行说明写明订阅更新会保留本地自定义 JSON，其他项目遵循订阅。更新后发现某个参数恢复为服务方值时，先比较覆写位置与订阅字段，不自动认定更新失败。保持测试分组简单，确认一个节点后再逐项加回自定义设置。

## 怎样判断已经恢复

更新完成后确认预期节点数量、一个节点的协议与端口，然后启动 VPN，用固定应用访问固定目标并观察连接日志。一次更新成功不等于每个节点有效。若列表正确而目标失败，继续阅读[DNS 排查](/articles/nekobox-dns-troubleshooting/)和[分应用路由](/articles/nekobox-app-routing/)。
