一个域名解析出多个 IP，其中部分地址连接较慢时，可以检查 mihomo 的 tcp-concurrent。官方定义是并发连接 DNS 解析得到的所有 IP，并使用第一个成功的连接。该字段不是把下载流量叠加到多个节点上。

## 修改前保留哪些信息

记录目标域名、DNS 返回地址、当前规则命中的出站和失败日志。只有一个可用地址时，并发选择的空间有限；域名根本没有解析结果时，应先修复解析。若问题出在代理节点认证或订阅过期，本选项也无法解决。

下面为顶层配置片段，需合并到已有有效 YAML，而非作为完整配置运行：

```yaml
tcp-concurrent: true
```

## 按同一条件验证

1. 备份配置，确认正在使用的是支持该字段的 mihomo 内核。
2. 固定节点、规则和目标域名，关闭已有测试连接后记录首次连接表现。
3. 仅修改 tcp-concurrent，加载配置并确认最终生效值。
4. 用相同应用重新发起连接，比较成功率、等待时间与错误类型。
5. 如结果变差，恢复原值并保留对照日志，不同时叠加多个网络开关。

这里讨论 TCP 建连；不要用 UDP 应用的结果直接验证该选项。已有长连接仍在复用时，也不适合拿页面刷新后的体感判断新建连接策略。

## 从结果继续定位

所有返回地址都不可达时，并发也不会产生可用连接。若开启后仍慢，应区分等待发生在 DNS 查询、连接建立还是后续传输。记录阶段比只保留一个总耗时更有助于反馈问题。

先核对 [mihomo DNS 解析路径](/articles/mihomo-dns-config-check/)，再按需要检查 [mihomo 规则顺序](/articles/mihomo-rule-order/)，避免测试流量实际走了不同出站。
