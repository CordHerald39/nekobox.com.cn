文件名写着 v2rayNG，或安装时没有报错，都不能单独证明 APK 来自原始发布者。项目 README 当前提供了 GPG 发布签名说明与公钥指纹。下载时应把发布来源、文件完整性和签名核验一起记录，避免只看文件名。

## 三种检查分别能说明什么

| 检查 | 能帮助确认 | 不能单独确认 |
| --- | --- | --- |
| 文件哈希 | 两份文件的字节是否相同 | 发布者身份 |
| GPG 发布签名 | 文件是否由对应私钥签署 | 你拿到的公钥是否可信 |
| Android 安装签名 | 更新包与设备现有应用的签名关系 | 下载网站是否属于官方 |

GPG 签名不是 Android 的安装证书。安装提示签名冲突时，应另查安装包渠道与已安装版本，不能靠重算哈希消除冲突。

## 从原始项目建立来源链

1. 从 [2dust/v2rayNG](https://github.com/2dust/v2rayNG) 的 README 进入 Releases。
2. 选择设备架构对应的 APK，记下发布标签、资产名称和原始下载地址。
3. 检查该次发行实际提供的签名或校验资料。没有找到对应文件时，记录为尚未完成签名核验，不假设所有历史资产都附带相同资料。
4. 从发布者明确提供的渠道取得公钥，将完整指纹与原始 README 对照；不能只比对末尾几个字符。

README 中的指纹应在下载当天重新核对。第三方文章抄录的指纹不能代替原始项目，单凭搜索到的同名公钥也不足以建立信任。

## 在电脑上验证分离签名

如果发布者为 APK 提供了分离签名，安装 GnuPG 并完成公钥指纹核对后，可以按其手册使用：

```text
gpg --verify <签名文件路径> <APK文件路径>
```

尖括号表示需要替换的真实路径，不是可直接粘贴执行的文件名。签名必须对应同一发行中的同一个 APK。出现缺少公钥、签名错误或文件不匹配时，保留原文件和错误输出，先重新核对来源与配对关系。

即便出现有效签名提示，也要确认签名者的完整指纹。未知公钥签出的有效签名不能替代发布者身份验证。

## 检查不通过时怎么办

先停止安装，重新从原始发行页下载并比对记录。不要用关闭系统保护、删除已有应用或忽略签名错误作为第一步。确实需要换渠道时，先备份个人配置，再阅读[下载与安装说明](/articles/v2rayng-android-download/)。订阅令牌和配置文件不应上传到公开签名检测网站。
