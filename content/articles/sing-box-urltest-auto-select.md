sing-box 的 `urltest` 会通过指定 URL 测试候选出站，用于自动选择节点。配置了自动组却看不到切换，先检查候选标签和流量是否进入这个组，再看测试间隔与容差。一次 HTTP 延迟测试只反映到测试目标的表现，不能直接当成下载速度、游戏延迟或所有网站的可用性结论。

## 建立一个便于比较的自动组

先分别验证两个已有出站，再把它们的 `tag` 放入自动组。下面只是 `outbounds` 内的一项局部示例；`proxy-a` 与 `proxy-b` 必须对应你自己的已配置出站，不提供节点或完整运行配置。

```json
{
  "type": "urltest",
  "tag": "auto",
  "outbounds": ["proxy-a", "proxy-b"],
  "interval": "3m",
  "tolerance": 50,
  "idle_timeout": "30m",
  "interrupt_exist_connections": false
}
```

官方文档将 `outbounds` 列为必填项，内容是待测试的出站标签。`url` 留空使用文档规定的默认测试地址；自定义时应选择稳定、可访问且能反映自己使用环境的 HTTPS 目标。不要使用含账户令牌的私人链接，也不要把返回慢的大文件下载页当成延迟测试目标。

## 为什么略快的节点没有立即接替

`interval` 是测试间隔，留空时默认 `3m`；`tolerance` 的单位是毫秒，留空时默认 50。它为选择行为提供容差，因此看到两个结果相差很小，不应直接判断为切换失效。`idle_timeout` 默认 `30m`，空闲情况也需要纳入观察记录。

建议先保留默认量级，不要为了看到切换把间隔压到几秒。频繁请求会增加测试流量，也更难区分网络波动与节点变化。一次只改一个字段，记录修改前后的时间、候选出站、测试目标和实际结果，再判断是否适合自己的网络。

## 配置正确仍不切换的检查顺序

1. 在运行时配置中确认自动组存在，而不是只编辑了未加载的文件。
2. 核对每个候选名称，包括大小写和前后空格；确认没有把自动组自身放入候选列表。
3. 确认受影响请求的路由最终指向 `auto`。流量直接指向某个节点时，自动组的测试不会改变该条路径。
4. 分别检查候选到同一测试 URL 的连接。如果所有候选失败，先排除共同测试目标的问题。
5. 等待完整测试周期后，重新发起一个短请求，查看实际出站，不要只观察原有的视频或下载连接。

如果流量根本没有被核心接管，可参考[TUN 入站配置检查](/articles/sing-box-tun-inbound-config/)；更换配置前先按[配置迁移与备份](/articles/sing-box-config-migration/)保存可回退版本。

## 已有连接与新连接分开验收

`interrupt_exist_connections` 控制切换时是否中断已有入站连接。官方文档还说明，内部连接不受此开关保护，会被中断。为了保留当前会话，不能仅凭字段为 false 就承诺所有连接都无影响。

验收时先做两个短请求，再观察长连接是否继续、重连后使用哪个出站。如果开启中断后出现业务掉线，恢复原值并重新测试。自动选择的目标应是可复现的选择行为，不是让页面上的延迟数字始终最低。
