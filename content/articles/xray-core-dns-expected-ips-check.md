Xray-core 的 DNS 服务器有响应，最终却没有可用地址时，需要检查返回结果是否被过滤。当前官方文档使用 expectedIPs 表示期望的 IP 范围，并配套说明 unexpectedIPs。应先核对实际核心支持的字段，再检查过滤范围与后备查询条件，不能仅凭服务器连通就认定解析链路正常。

## 过滤的是结果，不是访问路由

`expectedIPs` 配置在 DNS 服务器对象中。官方说明，设置后只返回符合列表范围的地址；`unexpectedIPs` 反向排除列表中的地址。它们影响 DNS 返回结果，不能代替连接路由中的 `ip` 条件，也不会自动把后续连接切到另一个出口。

以下 JSON 片段演示单个服务器对象里的过滤属性，范围采用本机回环网段，适合检查预期就应返回回环地址的本地记录。它不能替换完整 DNS 服务器对象，也不适合直接用于一般公网网站：

```json
{
  "expectedIPs": ["127.0.0.0/8"]
}
```

不要为了让公网查询通过就随意扩大范围。先明确要接受哪些地址、为何接受，再按实际服务修改。若使用 GeoIP 等外部数据条件，还需确认当前环境具有对应数据；本文示例没有依赖这类数据文件。

## 空结果之后会发生什么

官方流程先根据 `domains` 匹配构建优先服务器列表，再按后备条件补充其他服务器。默认串行查询时，失败或结果经 `expectedIPs`、`unexpectedIPs` 过滤后为空，会尝试最终列表中的下一台服务器。但如果候选列表已经被其他开关限制，就不一定有下一台可尝试。

`skipFallback` 为真表示该服务器不参加后备查询，并不表示它不能因 `domains` 命中进入优先列表。全局 `disableFallback`、`disableFallbackIfMatch` 以及单台服务器的 `finalQuery` 也会影响后续尝试。排查时把这些字段和服务器顺序一起记录，不要把所有回退开关当成同一种作用。

文档还说明，列表含 `*` 时，如果过滤后没有 IP，仍会返回原来的 IP。这个符号会改变过滤失败时的结果，不能在不了解含义时当作通用修复加入。需要强约束结果的场景尤其应先确认是否允许这种行为。

## 一次只检查一台服务器

1. 备份完整配置，记录核心版本、查询域名、查询类型和原始错误。
2. 对照当前版本文档核对字段拼写。本文与当前来源一致使用 `expectedIPs`；其他版本资料中的不同写法不能只凭名称推断兼容。
3. 检查该服务器的 `domains` 是否命中，确认它在最终候选列表中的位置。
4. 记录上游原始返回地址，再检查哪些地址应被接受、哪些应被排除；保留 A 与 AAAA 的区别。
5. 校验配置并重载，分别观察符合范围与不符合范围的受控目标，记录是否发生后备查询。

若实际版本不接受字段，立即恢复备份并查对应文档，不要尝试批量替换其他 DNS 键名。若过滤后有地址但访问仍失败，继续查出站和目标服务；DNS 校验成功不能证明 TCP 或 UDP 连接已经建立。

## 回退与相关检查

恢复该服务器原有过滤条件和后备开关，再用相同查询验证。不要直接删除全部 DNS 配置，否则容易同时改变解析路径与过滤行为，丢失问题证据。已有精确域名映射还应检查是否先被 hosts 处理。
