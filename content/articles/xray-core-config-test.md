Xray-core 下载完成后无法启动，先执行配置校验，比反复更换压缩包更容易定位问题。官方命令文档提供 `run -test`：它检查配置文件，不启动服务。检查通过后仍需另做监听与连接验证，不能把它当成节点可用性测试。

## 先固定程序与配置路径

在 Windows 上打开 PowerShell，进入自己解压的 Xray 目录。确认使用的是预期的 `xray.exe`，并将待检查的配置另存为副本。例如配置副本名为 `config.json` 时：

```powershell
.\xray.exe version
.\xray.exe run -test -config .\config.json
$LASTEXITCODE
```

第一行用于记录程序版本；第二行检查明确指定的文件；最后一行读取刚执行命令的退出码。路径有空格时要加引号。若实际程序或文件在别处，请替换为真实路径。

## 根据错误类别缩小范围

| 报错类别 | 检查方向 |
| --- | --- |
| 找不到配置文件 | 当前目录、文件名、扩展名与权限 |
| 语法或解析失败 | 错误位置附近的标点、括号、字段类型 |
| 字段不被识别 | 当前二进制版本与对应文档 |
| 引用的资源缺失 | 配置中的文件路径与资源部署位置 |

修改时保留原始错误，先修复第一条明确错误后重新检查。不要把真实服务器、用户标识、密钥或订阅 URL 贴进公开问题单。

## 多文件配置要按真实启动方式检查

官方文档支持重复传入 `-config`，也支持 `-confdir` 自动合并目录中的配置。如果日常启动依赖多个文件，只检查其中一个文件可能漏掉引用关系或合并差异。例如：

```powershell
.\xray.exe run -test -config .\base.json -config .\routing.json
```

这一命令仅适用于自己确实采用上述两个文件的情况。为排错准备专用目录，避免把旧副本和临时文件混在 `-confdir` 指向的目录里。需要查看合并结果时，可阅读官方 `-dump` 说明；输出可能含敏感配置，先在本地保存并脱敏。

## 配置通过后还要检查什么

按原来的启动方式启动服务，确认监听端口未被其他进程占用，再检查客户端接入与目标连接。配置校验无法证明远端认证、DNS、证书或网络路径正确。若更换了配置，失败时优先恢复可用副本，不要连续改动多个无关参数。

尚未分清核心与图形客户端时，先看[Xray-core Windows 下载说明](/articles/xray-core-windows-download/)。本文命令依据核验当天的官方文档；使用旧版本时，应同时检查本机帮助输出和对应发行说明。
