sing-box 节点能连接，远程规则集仍可能更新失败。规则文件有自己的下载路径、格式和更新周期；先记录具体规则集的 tag 与报错，再判断失败发生在请求、解析还是使用阶段。本文针对 sing-box 配置中的 `route.rule_set`，不是客户端订阅列表，也不适用于 mihomo 的 YAML 规则集合。

## 先确认规则集是哪一类

官方文档区分 `inline`、`local` 与 `remote`。内联规则没有远程更新；本地文件应检查 `path` 所指文件；只有远程规则集使用 `url` 下载。把三个类型混在一起排查，会出现修改订阅地址却始终无效的情况。

在配置副本中找到出错的规则集，逐项记录：

| 字段 | 应检查的内容 |
| --- | --- |
| `tag` | 名称是否与日志和引用处一致 |
| `type` | 是否确实为 `remote` |
| `url` | 是否仍为提供方给出的规则文件地址 |
| `format` | `source` 对应源格式，`binary` 对应二进制格式 |
| `update_interval` | 是否误把长更新周期当成更新未发生 |

文档允许在路径或 URL 使用 `.json`、`.srs` 扩展名时省略格式。没有这些扩展名时，应明确填写格式，不要仅根据响应的 MIME 类型猜测。浏览器能打开地址，也可能只得到登录页或服务商错误页，不能证明正文是规则文件。

## 按版本检查下载路径

先运行 `sing-box version`，或在客户端查看实际内核版本。当前官方文档标出 `http_client` 从 1.14.0 起提供，而旧的 `download_detour` 从该版本起弃用。旧核心与新文档的字段不能直接互换，升级建议先看[配置迁移与备份](/articles/sing-box-config-migration/)。

1. 保留可用配置和规则文件副本，避免清掉唯一可工作的缓存。
2. 用与已安装核心对应的文档确认下载字段，检查引用的 HTTP client 或出站是否真实存在。
3. 在相同网络条件下检查规则地址的状态与正文。不要把含令牌的地址贴入在线测试工具。
4. 如果日志显示解析失败，先核对源格式与二进制格式，再检查提供方是否更换了文件类型。
5. 若下载路径经过某个代理，先单独验证该代理；其启动又依赖同一规则文件时，应检查是否形成相互依赖。

`update_interval` 留空时，文档给出的默认值为 `1d`。手动测试成功后，应观察下一次约定周期的日志，不能因为几分钟内没有再次请求就缩短到每秒重试。

## 文件更新了，分流却没有变化

这属于使用阶段。检查路由或 DNS 规则是否引用了该 `tag`，并确认测试目标确实在规则内容内。新建测试连接，记录实际出站；仅看文件修改时间无法证明规则命中。涉及 DNS 结构变化时，再按[DNS 服务器配置迁移](/articles/sing-box-dns-server-migration/)核对版本。

官方文档说明，开启 `experimental.cache_file.enabled` 后远程规则集会缓存。缓存可帮助恢复运行，却不能证明本次网络更新成功。验收应同时保留请求结果、解析结果与目标请求的行为记录。失败时恢复原配置，继续使用已核验的文件，避免在未知原因下反复删除缓存。
